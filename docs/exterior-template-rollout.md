# Exterior service template rollout

All ten exterior service routes now use `components/exterior-service-page.js` and the approved vinyl page CSS. The section order, grids, typography, image frames, responsive rules, shared navigation and footer remain consistent. The original vinyl entry point delegates to the shared component; its visible main-page text and element sequence were compared with the pre-refactor build and preserved.

Nine additional material-specific profiles live in `data/exterior-template-content.json`. They extend the existing service catalogue with suitability checks, scope, process, coating/colour considerations, quote factors, local context and six FAQs. Brick painting/staining, soffit ventilation and drainage, window operation, door access and commercial work zones are handled individually. The form receives the current service title, path, slug and project prompts, and downloads a correctly named local draft ZIP. No online submission is claimed.

Existing service-specific hero/detail and company photographs are reused with their source alt text and known dimensions. Two newly generated window photographs distinguish Window Painting from Door Painting. Other company gallery images are presented as separate examples, not false before/after pairs. Vinyl retains its explicitly illustrative transformation and original crops. The window image-generation briefs requested charcoal exterior window frames on a pale masonry house, and a close application detail on a masked exterior timber frame; built-in image generation was used. Assets are WebP files in `public/images/subservices/window-painting/`.

Validation: production build; 16 service routes with unique metadata; ten exterior pages with identical section structure, six FAQs and distinct hero images; service-specific form defaults; internal links and anchors; sitemap and schema; image references and decodable new assets; collapsed menu assertions; CSS parsing and shared mobile/tablet breakpoints. A snapshot comparison checks vinyl text and element order. Form transport remains a local draft; no email delivery was added.

Supported browser control is unavailable in the managed environment. Rendered desktop/tablet/mobile screenshots, visual overflow measurements and pixel-perfect device sign-off are not claimed. Existing responsive CSS is shared by every exterior route; automated checks cover structure and assets rather than rendered appearance.
